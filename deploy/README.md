# Styx 2 — RU-вход (белые списки) → США

Два сервера, четыре профиля у каждого клиента, мониторинг всех цепочек, персональные подписки и учёт устройств онлайн.

```
                        ┌──────── RU/entry (IP из белого списка) ────────┐           ┌────────── US/exit ───────────┐
 Клиент ──TCP 443──────►│ Xray  VLESS+Reality+Vision (SNI белого списка) │  us-xhttp │ Xray  :8443 XHTTP+Reality    │
 Клиент ──UDP 443/hop──►│ Hysteria2 + Salamander ──► local SOCKS ──┐     │ ════════► │ (только с RU IP)             │
                        │                                          ▼     │  us-vision│ Xray  :443  Vision+Reality   │──► интернет
                        │  маршрутизация Xray:                           │ ════════► │ Hysteria2 :443 + hopping     │
                        │   ru-blocked              → США                │  us-hy2   │                              │
                        │   .ru / geoip:ru / RU-only → напрямую с RU IP  │ ════════► │ Caddy  :2096 подписки+Grafana│
                        │   остальное               → балансер США       │           │ Prometheus/Alertmanager/...  │
                        └────────────────────────────────────────────────┘           └──────────────────────────────┘
 Клиент ──TCP/UDP 443 ─────────────────────── запасной профиль «США напрямую» ──────────────────────────►
```

**Что внутри:**

| | |
|---|---|
| Вход по RU IP | VLESS + Reality + Vision на TCP 443, Reality-SNI из белого списка. Hysteria2 + Salamander на UDP 443 с port hopping 20000–50000 |
| Туннель RU → US | Три канала: XHTTP + Reality (основной), Vision + Reality и Hysteria2 + Salamander с hopping. Xray-балансер каждые 30 с меряет задержку и уводит трафик с мёртвого канала |
| Маршрутизация на RU-ноде | Российские сайты выходят с российского IP: банки, Госуслуги и маркетплейсы работают. Заблокированное в РФ идёт через США |
| Hysteria2 | Salamander, port hopping, настоящий сертификат Let's Encrypt (без `insecure`), отдельный пароль у каждого клиента, онлайн и трафик по пользователям, ACL против доступа к локальным портам |
| Мониторинг | Пробы через настоящих клиентов по всем пяти цепочкам. RU-нода мониторится через сам туннель, наружу она не открывает ни одного порта мониторинга. Grafana, алерты в Telegram, dead man's switch |
| Клиенты | Персональная подписка-ссылка с токеном. Happ получает правила маршрутизации deeplink-ом, v2RayTun — заголовком. Видно, сколько устройств онлайн у каждого |
| Хост | BBR + fq, буферы UDP под QUIC, conntrack, nftables с default-drop, swap, ротация логов, автообновления безопасности |

## 1. Что купить

### US/exit (выход в интернет + мониторинг + управление)

| Параметр | Рекомендация | Почему |
|---|---|---|
| Виртуализация | **KVM** (не OpenVZ/LXC) | нужны своё ядро, BBR, nftables, sysctl |
| CPU | **2 vCPU**, лучше dedicated/высокий приоритет | Reality и QUIC шифруют на CPU. 30 человек × 50–100 Мбит/с упираются в CPU |
| RAM | **4 ГБ** (минимум 2 ГБ, тогда swap включится сам) | Prometheus + Grafana + Xray + Hysteria ≈ 1.2–1.5 ГБ |
| Диск | 30–40 ГБ NVMe | метрики хранятся 60 дней (до 3 ГБ) |
| Порт | **1 Гбит/с** | 100 Мбит/с — мало даже для 10 человек вечером |
| Трафик | **≥ 4 ТБ/мес** или безлимит | 30 человек × 100 ГБ ≈ 3 ТБ, трафик через RU-вход тоже приходит сюда |
| IP | выделенный IPv4 (IPv6 — бонус) | |
| Локация | **Восточное побережье**: Нью-Йорк, Нью-Джерси, Ашберн (Вирджиния) | ~110–140 мс до Москвы. Западное побережье — 170–200 мс |
| ОС | **Ubuntu 24.04** | под неё написан bootstrap |

**Как выбирать хостера:**
- Не бери крупных хостеров, чьи подсети массово режутся из РФ: Hetzner, OVH, DigitalOcean, AWS. Лучше средние KVM-хостеры с локацией в NY/NJ.
- Проверь ToS: прокси/VPN не запрещены. Торренты в конфиге заблокированы, чтобы не ловить DMCA-жалобы.
- Возьми помесячно, не на год. Первым делом проверь:
  - пинг из РФ;
  - что IP не в чёрных списках, а ChatGPT и Netflix открываются без капчи;
  - что VLESS с домашнего интернета работает.

  IP плохой — проси замену или меняй хостера.

### RU/entry (вход из белого списка)

Это самый капризный элемент. Белые списки зависят от оператора и региона и меняются. Гарантированного хостера нет, есть только проверка на практике.

| Параметр | Рекомендация |
|---|---|
| Где | **Yandex Cloud** или **VK Cloud**: про них чаще всего сообщают, что IP попадают в белые списки. Классические хостеры — редкая удача |
| vCPU | **2 vCPU, гарантированная доля 100 %** (в YC не бери 20 % и 50 % — будет тормозить) |
| RAM | 2 ГБ |
| Диск | 15–20 ГБ SSD |
| IP | **публичный статический IPv4** (зарезервировать после того, как найдёшь «белый») |
| ОС | Ubuntu 24.04 |
| Группа безопасности (firewall облака) | разрешить входящие: TCP 22, TCP 443, UDP 443, UDP 20000–50000 (+ TCP 8444, если MTProto). Остальное закроет nftables |

**Как найти белый IP:**
1. Создай ВМ с публичным динамическим IP.
2. Проверь IP по спискам сообщества ([kort0881/russia-whitelist](https://github.com/kort0881/russia-whitelist)). Лучше проверь вживую: с телефона на мобильном интернете в режиме белых списков сервер должен пинговаться и отвечать на TCP 443.
3. IP не подходит — освободи его и выдели новый. Иногда нужен новый каталог или проект: адреса выдаются из пулов.
4. Нашёл — **сделай IP статическим** и только потом плати надолго.

**Учти:**
- В облаках платный **исходящий трафик**. Через RU-вход каждый гигабайт выходит дважды: к клиенту и в США. Посмотри тариф и прикинь бюджет. Для 30 человек это может быть заметная сумма.
- Облака иногда блокируют ВМ за VPN. Поэтому у клиентов всегда есть профиль «США напрямую», а бэкап `state/` позволяет поднять вход на новом IP за 5 минут.

### Домен

Подойдёт любой регистратор. DNS удобно держать в Cloudflare, **без проксирования (серое облако)**.

| Запись | Тип | Значение |
|---|---|---|
| `sub.example.com` | A | IP US-ноды |
| `hy.example.com` | A | IP US-ноды |

На RU-ноду DNS-записи не нужны: клиенты подключаются к ней по IP.

### Telegram

1. Создай бота у [@BotFather](https://t.me/BotFather) и сохрани токен.
2. Напиши боту что-нибудь, затем открой `https://api.telegram.org/bot<TOKEN>/getUpdates`. Поле `chat.id` — это твой chat_id. Для группы id отрицательный.
3. Желательно: бесплатный чек на [healthchecks.io](https://healthchecks.io) с периодом 5 минут и grace 5 минут. Его URL — это dead man's switch: он присылает алерт, если US-нода умерла целиком вместе с мониторингом.

## 2. Reality SNI — подобрать правильно

Для Reality нужен «чужой» сайт с TLS 1.3 и HTTP/2. Лучше всего — сайт в **той же подсети или ASN**, что и сервер: снаружи всё выглядит естественно.

```bash
# на сервере (или откуда угодно), сканируем соседей своего IP
wget https://github.com/XTLS/RealiTLScanner/releases/latest/download/RealiTLScanner-linux-64 -O scanner && chmod +x scanner
./scanner -addr <IP_СЕРВЕРА> -port 443 -thread 50 -timeout 5 -out found.csv
```

Из `found.csv` выбери домен с `TLS 1.3` и `h2`, который не прячется за CDN и открывается браузером.

- **RU-нода:** домен обязан быть **в белом списке**, иначе DPI зарежет по SNI. Возьми найденный сканером домен в сети Yandex Cloud или VK Cloud и сверь его со списком.
- **US-нода:** любой подходящий сосед.

## 3. Установка

Всё управление идёт с US-ноды. RU-ноду `styxctl` настраивает сам по SSH.

**Шаг 1. US-нода**
```bash
git clone <repo> /opt/styx-src && cd /opt/styx-src
sudo bash deploy/host/bootstrap.sh exit
cd deploy && sudo ./styxctl init        # ответить на вопросы; в конце выведет SSH-ключ управления
```

**Шаг 2. RU-нода.** Подставь ключ, который вывел `init`:
```bash
# скопируй deploy/host/ на RU-ноду (scp) или curl с raw-ссылки репозитория
sudo bash bootstrap.sh entry "ssh-ed25519 AAAA... styx-control"
```

**Шаг 3. Снова US-нода**
```bash
sudo ./styxctl geo-update               # geoip/geosite от runetfreedom (ru-blocked, category-ru, ...)
sudo ./styxctl user add ivan --note "Иван, телефон"
sudo ./styxctl deploy                   # проверка конфигов xray -test → US → RU
sudo ./styxctl status
```

При первом `deploy` Caddy выпускает сертификаты (до 1–2 минут), и только после этого стартует Hysteria2 на обеих нодах. Если сертификат не успел выпуститься, повтори `deploy`.

## 4. Клиенты

```bash
sudo ./styxctl user add masha          # создать → выдаст ссылку-подписку + QR в терминале
sudo ./styxctl user show masha         # ещё раз показать ссылку/QR
sudo ./styxctl user list
sudo ./styxctl user disable masha      # временно отключить (подписка тоже перестаёт отдаваться)
sudo ./styxctl user enable masha
sudo ./styxctl user rotate masha       # новые ключи + новая ссылка (если ссылка «утекла»)
sudo ./styxctl user del masha
sudo ./styxctl status                  # кто онлайн, сколько устройств, трафик за 24ч, состояние цепочек
```

У каждого клиента одна ссылка `https://sub.example.com:2096/s/<токен>`. В ней четыре профиля:

| Профиль | Когда |
|---|---|
| 🇷🇺→🇺🇸 RU-вход · VLESS | **основной**: мобильный интернет с белыми списками, любые блокировки |
| 🇷🇺→🇺🇸 RU-вход · Hysteria2 | быстрее на плохих сетях, если UDP не режется |
| 🇺🇸 США напрямую · VLESS | если RU-вход недоступен; домашний Wi-Fi |
| 🇺🇸 США напрямую · Hysteria2 | максимальная скорость дома |

**Сколько подключений:**
- VLESS считает **уникальные IP** онлайн.
- Hysteria2 считает **запущенные клиенты**, то есть устройства.

Данные есть в `styxctl status` и в Grafana: «Кто онлайн сейчас» и график по каждому пользователю. Если у одного человека постоянно 5+ устройств, значит ссылкой поделились: сделай `user rotate`.

**Можно ли одну ссылку на всех?** Можно: создай одного пользователя, например `shared`, и раздай его ссылку. Но тогда не видно, кто именно онлайн, и нельзя отключить одного человека. Для 15–30 человек персональные ссылки лучше.

Добавление, удаление или отключение пользователя перезапускает Xray и Hysteria. Подключённые клиенты переподключатся за 1–2 секунды.

### Приложения

| Платформа | Приложение | Импорт | Заметки |
|---|---|---|---|
| iOS / Android / macOS / Windows | **Happ** | «+» → вставить ссылку или `happ://add/<ссылка>` | правила маршрутизации приходят сами (RU — напрямую) |
| iOS / Android | **v2RayTun** | «+» → «Импорт из буфера» или `v2raytun://import/<ссылка>` | правила приходят заголовком `routing` |
| iOS | **Shadowrocket** | «+» → Type: Subscribe → URL | режим маршрутизации «Config»: дефолтный конфиг Shadowrocket пускает RU-сайты напрямую |
| все + **Linux** | **Hiddify** | «Новый профиль» → ссылка | Настройки → Регион → **Russia**: RU-сайты пойдут напрямую |
| Linux / Windows | **Throne** (бывш. NekoRay) | Server → New subscription | для Linux это, скорее всего, тот клиент, который ты вспоминал |
| Linux CLI | официальный `hysteria` | конфиг из ссылки | единственный клиент с полным port hopping |

**Port hopping.** В ссылке Hysteria2 основной порт 443, диапазон передаётся параметром `mport=20000-50000`. Hiddify и Throne его понимают и прыгают по портам. Остальные клиенты просто работают через 443.

## 5. Мониторинг и отказоустойчивость

**Grafana:** `https://sub.example.com:2096/grafana/`, логин `admin`, пароль показал `init` (лежит в `state/config.json`).

**Что проверяется каждые 30 секунд:**

| Проба | Как |
|---|---|
| RU-вход VLESS → США → интернет | отдельный клиент Xray на US-ноде ходит через RU-ноду, как обычный пользователь |
| RU-вход Hysteria2 → США → интернет | то же через Hysteria2 |
| RU-вход → RU-сайты напрямую | ya.ru через RU-ноду (проверка RU-direct) |
| США VLESS / Hysteria2 → интернет | прямые профили |
| Каналы RU → US (xhttp / vision / hy2) | observatory Xray на RU-ноде: alive и задержка каждого канала |
| TCP 443 обеих нод, HTTPS подписок, срок сертификата | blackbox |
| CPU / RAM / диск / conntrack обеих нод | node-exporter (RU — через туннель) |

**Алерты в Telegram:** не работает конкретная цепочка; RU-вход лежит целиком; умер канал RU → US (трафик уже ушёл на резервный); умерли все каналы; бэкенд не отвечает; CPU / RAM / диск; сертификат скоро истечёт; перезагрузка. Если умерла сама US-нода, срабатывает dead man's switch через healthchecks.io.

**Что происходит при сбоях:**

| Сбой | Что делает система |
|---|---|
| Режется один канал RU → US | балансер за ~30–60 с переводит трафик на другой, клиенты ничего не замечают |
| Лежит RU-нода или её IP выпал из белого списка | алерт. Клиенты вручную переключаются на профиль «США напрямую» |
| Режется UDP | VLESS-профили на TCP продолжают работать |
| Умерла US-нода | dead man's switch присылает алерт. Восстановление: новая VPS, копия `state/`, `deploy` |

## 6. MTProto (опционально)

```bash
sudo ./styxctl mtproto enable --domain <домен из белого списка>   # и сразу deploy
sudo ./styxctl mtproto show                                       # ссылка tg://proxy
sudo ./styxctl mtproto disable
```

Прокси работает на RU-ноде, порт 8444, режим FakeTLS. Трафик к серверам Telegram уходит через США.

## 7. Обслуживание

- **Бэкап:** весь `deploy/state/` (ключи Reality, пароли, пользователи, сертификаты). Без него все ссылки придётся перевыпускать.
- **Обновление geo-баз и сертификата:** таймер `styx-daily.timer` каждую ночь в ~04:20 обновляет geo-базы и копирует сертификат Hysteria на RU-ноду. Если базы изменились, Xray перезапускается.
- **Обновление версий:** поменяй теги в `state/config.json` → `"images"` и запусти `deploy`. По умолчанию версии закреплены (Xray 26.9.9, Hysteria v2.12.3).
- **Переезд RU-ноды на новый IP:** поменяй `entry_ip` в `state/config.json`, выполни на новой ВМ `bootstrap.sh entry "<ключ>"`, затем `deploy`. Ссылки-подписки у клиентов не меняются: обновление подписки подтянет новый IP само.
- **Логи:** `docker logs -f styx-xray`, `docker logs -f styx-hysteria`. На RU-ноде то же самое в `/opt/styx`.

### Порты

| Нода | Открыто наружу |
|---|---|
| US | TCP 22, 80 (ACME), 443 (Reality), 2096 (подписки/Grafana); UDP 443, 20000–50000; TCP 8443 **только для RU IP** |
| RU | TCP 22, 443; UDP 443, 20000–50000; TCP 8444 (если MTProto) |

Все порты мониторинга и API слушают только `127.0.0.1`.
